# 002 — The Launcher Scripts

**File:** `src/haiv_project/commands/dev/install.py`

## Why I came here

This is where the process chain begins. Before anything runs inside WezTerm, something has to invoke `hv start`. On Windows, there are two launcher scripts — both installed by this command. I need to understand what they spawn, because that's process #1 in the tree.

## What I found

`hv dev install` generates launcher scripts in `~/.local/bin/`. Two per tool on Windows:

**Bash script** (extensionless — for git-bash, WSL, Claude Code):
```bash
export HV_PROG="$(basename "$0")"
unset VIRTUAL_ENV
exec uv run --project ".../haiv-cli" python -c "from haiv_cli import main; main()" "$@"
```

**CMD script** (.cmd — for cmd.exe, PowerShell):
```cmd
set HV_PROG=%~n0
set VIRTUAL_ENV=
uv run --project ".../haiv-cli" python -c "from haiv_cli import main; main()" %*
```

Key difference: the bash script uses `exec`, which *replaces* the shell process with `uv run`. The CMD script just calls `uv run` as a child — the cmd.exe process stays alive until uv exits.

**Process lifecycle at this stage:**
- **Bash launcher:** dies immediately (replaced by `exec`). Process becomes `uv run` → `python`.
- **CMD launcher:** stays alive as parent of `uv run` → `python`. Exits when python exits.
- Both invoke `uv run`, which spawns `python -c "from haiv_cli import main; main()"`.
- The `uv run` process is a wrapper — it sets up the venv and launches python. It stays alive while python runs.

**On Windows, Claude Code uses the bash script** (since Claude Code runs in a bash-like environment). So the process tree starts: `bash` → (exec) → `uv` → `python` → `haiv_cli.main()`.

**Orphan risk:** None yet at this stage. These processes exit when the command finishes. The interesting part is what `main()` does next.

**Note:** `haiv-core/commands/start/_index_.py` is just `ctx.tui.start()` — pure delegation. The real logic is in `terminal.py`.
