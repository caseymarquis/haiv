# 004 — The Pop Command

**File:** `worktrees/main/haiv-core/src/haiv_core/commands/pop.py`

## Why I came here

I need to understand what pop assumes about worktrees and sessions so I can make it handle autonomous and no-worktree minds gracefully.

## What I found

Pop is 172 lines with three modes: bare (checklist), `--merge`, and `--session`.

**The checklist (`_print_checklist`, line 47):**
- Gets the current session via `HV_SESSION` env var
- If the session has a parent, scaffolds an AAR in the parent mind's directory
- Lists steps: review, improve, discuss, test, commit, fill AAR, merge, remove session
- Uses `ctx.mind.checklist()` — a mind-level helper I haven't seen before

**The merge (`_do_merge`, line 88):**
- Gets current session, reads `branch` and `base_branch`
- **Hard fails if either is missing** (line 92-97) — `CommandError("Session is missing branch or base_branch metadata")`
- Uses `ctx.git.at_worktree(base_branch)` to run git from the base branch's worktree
- Checks if branch exists, checks if it has commits ahead, merges if so
- Removes the worktree and deletes the branch

**The session cleanup (`_do_session`, line 133):**
- Requires a parent session (can't pop a root session this way)
- Sends a notification to the parent mind's pane via TUI
- Removes the session
- **Clears `work/` directory** (line 163-167) — `shutil.rmtree(work_dir)` then `mkdir()`. This wipes the assignment for next use.
- Refreshes TUI, launches parent mind, closes this mind's pane

## What surprised me

**`_do_merge` hard-fails without branch metadata.** This is the primary blocker for no-worktree minds. If a mind has no worktree, there's nothing to merge — but `--merge` will crash. For no-worktree minds, pop needs to either skip the merge step entirely or provide a different flow.

**The checklist is worktree-centric.** Steps like "Commit all changes to your worktree branch" and the merge step don't apply to worktree-less minds. The checklist would need a different variant.

**`_do_session` clears `work/` — this is mind recycling.** After pop, the mind is a clean slate for the next assignment. This works regardless of worktree status, which is good.

**The parent notification assumes a TUI pane.** `ctx.tui.mind_try_send_text` is best-effort (the "try" suggests it handles missing panes), but autonomous minds might not have a pane at all. Worth checking if this is truly safe.

**Pop has no concept of "mode."** It's purely session-and-worktree-aware. Adding mode awareness means pop needs to check the session metadata and branch its behavior.

## What this means for my task

For no-worktree minds:
- `--merge` should either be a no-op (with a message) or not appear in the checklist
- The checklist should omit worktree-specific steps
- `--session` works as-is (session removal, work/ cleanup, TUI refresh are all worktree-agnostic)

For autonomous minds:
- The checklist might be different (no "discuss your findings" step — there's nobody to discuss with)
- The AAR process might change (autonomous minds might auto-generate AARs?)
- Or maybe the checklist is fine as-is for autonomous — the mind just follows it without human interaction

The session's `mode` and `has_worktree` (or empty `branch`) fields would drive these conditional behaviors.
