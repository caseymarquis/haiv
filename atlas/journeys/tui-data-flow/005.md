**File:** `worktrees/main/haiv-lib/src/haiv/helpers/tui/helpers.py`

## Why I came here

This is where the atlas says "all real logic lives." I needed to find where session data and git data get combined into `SessionEntry`.

## What I found

`sessions_refresh` (lines 41-73) is the exact point where gather and assemble are tangled. The function:

1. Loads sessions from TOML (`load_sessions`)
2. For each session, calls `git.branch_stats(s.branch, s.base_branch)` — this is a subprocess call per session
3. Merges both into a single `SessionEntry` with session fields + git fields
4. Writes the combined list into the model

The git call is wrapped in try/except that silently swallows failures (line 63: `pass`). So if git fails, you get `BranchStats()` defaults (which based on TuiModel are -1 sentinel values). The flakiness: sometimes git works, sometimes it doesn't, and you can't tell from the UI which case you're in.

**The performance problem is also visible here.** For N sessions, this makes N sequential `git.branch_stats()` subprocess calls, all blocking inside a single `sessions_refresh` call. If any of those calls is slow, the entire session list goes stale.

**Important detail:** `git` is an optional parameter (default `None`). The function already works without git data — it just uses `BranchStats()` defaults. This means the separation is half-designed already. Someone anticipated that git might not be available.

**`mind_launch` also calls `sessions_refresh` with git** (lines 140, 148, 154). So every mind switch/launch triggers a full session+git reload. If git is slow, launching feels slow.

**Other observations:**
- `build_claude_command` and `build_env` have a self-aware comment: "These aren't really TUI concerns... they should move if a better home emerges." Honest code.
- The `_set_entries` mutator is separated "for picklability" — suggests the client/server boundary involves serialization (IPC, not just in-process).

## The redesign crystallizes

The current flow: `sessions_refresh` gathers both → assembles both → writes one section.

The new flow:
1. `sessions_refresh` gathers sessions only → writes `SessionsSection`
2. A separate `git_refresh` gathers branch stats → writes `GitSection`
3. Widgets merge at render time by matching session branch to git data

The `git` parameter on `sessions_refresh` just... goes away. `mind_launch` calls them separately (or just sessions, letting the poll loop handle git).
