## Why I came here

Confirming that the bare `hv chart` command doesn't reference example journeys. If it does, my change has a wider surface area than I thought.

## What I found

It doesn't. This is purely a text-output command — builds a briefing string with hardcoded atlas guidance (finding advice, charting rules, rewards) and prints it. No templates, no file lookups, no example references. The only filesystem interaction is ensuring `journeys/` and `maps/` directories exist.

**But — potential coupling I almost missed.** `_index_.py` doesn't reference examples *today*, but should it once examples are project-local? Two things to consider:

1. **Atlas structure bootstrapping.** `_index_.py` line 24 ensures `journeys/` and `maps/` exist. If I add a project-local examples folder, should `_index_.py` also ensure *that* exists? Or should only `explore.py` handle it (since it's the one that uses examples)? If a mind runs `hv chart` before `hv chart explore`, should the examples folder already be there?

2. **Should `hv chart` mention examples?** The bare command is a briefing — it tells minds how to use the atlas. Once project-local examples exist, it might be useful for `hv chart` to say "check the example journey before you start exploring." That would be a new coupling point between the two commands.

These aren't blockers for my task, but they're design decisions I should discuss before implementing.

**Observation for the quest board:** This whole file is hardcoded strings built with `lines.append()`. If the charting rules ever need to change, you'd edit them in two places — here and in `atlas/welcome.md` (which has the same content). That's a potential consistency issue, though maybe intentional since `welcome.md` is project-customizable while this is the core default.
