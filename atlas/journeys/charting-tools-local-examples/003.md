## Why I came here

Entry 002 revealed that `_find_example_journey()` passes an example path to this template. I needed to see how it's consumed — and whether the template hardcodes specific filenames.

## What I found

It does. Lines 12-13:
```
  {{ example_journey }}/001-research-log.md
  {{ example_journey }}/002-the-resolver-infrastructure.md
```

The template hardcodes two specific files from the resolver system journey. This is the second coupling point: not only does the code point to a bundled asset path, but the template assumes specific files exist there.

For project-local examples, this needs to change. Different projects will have different example journeys with different filenames. Two options:
1. The template dynamically lists whatever files are in the example folder
2. The command passes the list of files to the template

Option 2 is cleaner — keeps the logic in Python, keeps the template dumb. The command can glob the example folder and pass the file list.

**One more thing:** The `{% if example_journey %}` block means the whole "BEFORE YOU BEGIN" section is optional. If no example exists, it just skips to the research log instructions. That's good — means a fresh project with no examples yet still works. But my task says to auto-populate from the template on first run, so this fallback might rarely trigger.
